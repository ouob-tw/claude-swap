# 一般切換的週重置排序

來源：2026-10-09 使用者回報帳號一達上限後切到帳號二，但帳號三更快重置；帳號三週用量 85%，帳號二約 14%。使用者已手動選取帳號三，要求確認並修復。

- 一般達門檻、額度用盡及故障備援切換，優先選「週剩餘額度（100 − 週用量%）÷ 距離週重置的小時數」最大的合格帳號，讓剩餘額度多但較晚重置的帳號也能被使用。
- 數值相同時，選週重置較早的帳號，不能用 5HR 或綜合剩餘額度替代。閒置預選不論策略都使用此排序；目前帳號與最佳候選數值相同時，優先保留目前帳號。
- 維持 94% 觸發線；5HR 用量達到 94% 的帳號禁止切入，須由新額度讀值確認恢復。
- 缺少週重置時間或有效週用量的候選帳號不參與此排序。
- 未達門檻的忙碌工作階段保留目前帳號，包含使用者手動選取的帳號三。原有閒置及快取條件仍控制預選。
- 以新增 `weekly-reset` 策略實現並更新此主機的設定及背景服務；原有其他策略保留。

驗證：使用隔離帳號檔案與模擬額度重現本次資料，測試達門檻、用盡、備援、相同週重置時間、94% 切入限制、未知重置及手動帳號保留；完整既有測試通過後更新背景服務，確認載入設定與目前帳號。

後續使用者調整：5HR 仍以 94% 為切換與切入限制；7 天額度改成 99% 才切換。週用量 94～98.99% 不可獨自觸發切換，週用量已達 99% 的候選帳號不切入。以 `autoswitch.sevenDayThreshold=99` 設定週門檻；未設定時維持原本共用門檻的行為。閒置預選仍適用候選限制。
